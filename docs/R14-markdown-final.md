## 实现

### 解析与 span 适配

`MarkdownParser.kt` 用本地、无副作用的块/内联语法树替代跨全文多轮正则替换：

- ATX 1–6 级标题与 Setext 标题；普通多行段落；分隔线。
- 无序列表、有序列表（保留起始编号）、缩进嵌套、常见续行、松散列表与只读 GFM `[ ]`/`[x]` 任务项。
- 嵌套引用及普通引用段落的 lazy continuation。
- 反引号或波浪号围栏、可变长度闭合、语言标签、未闭合围栏消费至当前容器末尾、缩进代码。闭合围栏必须独占一行，不能再把代码行中途出现的三个反引号误当作闭合。
- GFM 管道表格：可选外侧管道、对齐冒号、转义管道、代码 span 中的管道、短行补空单元格、超出表头的单元格按 GFM 规则忽略；不匹配的分隔行回退普通文本。
- `*`/`_` 强调与加粗、常用嵌套和相邻组合、`***`、`~~删除线~~`、转义标点、常用实体/数字实体、硬换行、多反引号行内代码。
- 显式链接支持带样式/代码的标签、平衡括号的 HTTP(S) 目标、可选引号标题与 `<https://…>` 自动链接形式。裸 URL 不会自动变为可点击能力。

`MarkdownText.kt` 保留 `render(source): CharSequence` 接口，按树生成真实 spans，提供块及内联适配。所有范围使用 UTF-16 索引，不再依赖替换后的偏移修正。标题、引用、代码块、分隔线保留块元数据；Compose 布局直接消费同一语法树。兼容接口的表格是可读的纯文本行，而真实聊天走下面的网格布局。

### 生产渲染

`MessageMarkdown.kt` 保留现有入口及 `markdown=false` 的原文语义：

- 单段文本仍保留原来的 tagged `BasicText` 节点，避免破坏现有内容分段和测试定位。
- 整个正文仍置于 `SelectionContainer`，标题、列表、引用、代码与表格单元格均为真实文本而非图片/WebView。
- 标题字号、引用边线、只读列表标记、代码背景、表格边框/表头均使用现有 Miuix 字体/调色板；不引入另一套主题。
- 代码块不运行高亮脚本、不加载语言插件；长代码行可软换行。
- 表格每列宽度有界（120–248 dp），单元格长文本换行，不设 `maxLines` 或省略号；整个对齐网格共享横向滚动状态，外层按聊天可用宽度裁剪。不会把长内容强压进固定总宽或撑宽聊天气泡。
- 极端超过 32 列的表格按列分组展示，每组仍可横滚，避免超出 Compose 有限约束编码；不丢弃表头范围内的列/单元格。行按正常消息内容纵向排布，不加固定高度嵌套滚动窗。

### 安全与流式输入

- 围栏/缩进代码在其他块之前消费；行内代码先独立成 token，不在其内部解释表格、强调或链接。代码字面量中的危险/安全 URL 均不额外生成点击能力。
- 原始 HTML 只作为可见文本，不交给 HTML 引擎、浏览器、图片加载器或脚本执行器。Markdown 图片、HTML 图片不触发网络加载；既有消息图片投影不在本任务范围。
- 保留严格的小写 HTTP(S) 白名单，拒绝凭据、无主机、控制字符、空白、反斜杠及非法端口。拒绝目标的显式链接保留字面形式，不解码/修复为另一个可点击 URL。
- spans 转 Compose 时再次筛选安全 URL，点击回调在调用 `UriHandler` 前再检查；解析/重组/普通点击不打开 URI，缺失外部处理程序不会抛出到 UI。
- 未闭合行内语法保留字面文本；未闭合围栏按代码显示。括号与反引号运行提前建索引，避免常见长未闭合输入的重复全文扫描。容器/内联递归上限 24；强调扫描具有线性比例预算，超过预算或复杂度上限的剩余分隔符保持字面可读，不截断消息。

## 本轮复杂度修复（候选基线 `2ebd2ba`）

本轮净改动仅在 `MarkdownParser.kt`、`MarkdownParserTest.kt` 和本文档；未改 Main、Controller、重构清单、Compose 消费者、CI 或依赖。工作树净差异应由父代理合并后再次核对，本环境无法独立核验 Git 暂存区或产生提交。

### 链接目的地：整段共享线性工作预算

- 已确认反例：`"[x](".repeat(n) + " q" + ")".repeat(n)` 括号平衡，旧代码仍会从每个候选起点重复扫描长 URL 并提前 `substring`，形成 Θ(n²)。单独预索引括号并不足够。
- 同一 inline 调用的所有显式链接候选共享 `8 * UTF16长度 + 64` 的 `Long` 工作预算。URL（含尖括号形式）、空格/tab、引号标题（包括未闭合标题）、失败路径的扫描均扣账；复制 URL 与后续安全 URI 校验另按 URL 长度预留预算。扫描失败时不再提前复制 URL，标题不再使用无预算 `indexOf`/`substring`。
- 预算耗尽即返回**整个当前 inline 原文**的单个 Text 节点，包括先前的实体、转义、强调，不对尾部再次解析，也不截断文本。计数上限与 UTF-16 源长度线性相关，现有深度上限、URI 白名单和代码隔离不变；未扩展 CommonMark 范围。
- 新增确定性工作计数回归：n=32/512/4096 的平衡畸形 URL、共享长空白、单/双引号未闭合标题、闭合标题后的长空白失败；另检查长合法 URL/空白/标题、单个长未闭合标题、Unicode 原样回退和凭据 URI 拒绝。不使用墙钟阈值。

### 表格：padding/Compose 节点之前预检总体预算

- 每张表先读取显式行，使用 `Long` 累加表头在内的总单元格及缺失单元格数；上限分别为 **16,384 cells** 和 **4,096 隐式空单元格**（等于上限仍允许）。在通过整个表格的预检之前，不补空、不解析单元格 inline AST、不生成 Table 节点。累加一旦越界即饱和停止计数/保留待构造行，避免 Int 乘法溢出或继续积累虚拟矩阵。
- 任一预算超限，整个原始表格（表头、分隔行、全部显式行及超出表头的尾列）作为一个无语言标签 Code 字面块保留，消费到正常表格边界；不丢后续行、不将超限行当作新的 Markdown。此处复用已有可选择、软换行的惰性代码文本渲染，AST/Compose 节点数量不再随宽×高膨胀，文本存储仍与显式输入成正比。
- 32 列分组仅处理正常预算内表格的布局约束，不作为总量防护。普通表格的 GFM 补空/忽略超表头列语义不变，只有超预算回退才逐字保留这些额外列。
- 回归源码覆盖 4096 列×4096 个 `x |` 短行，并附额外尾行/尾列及独立后续段落；断言只得到一个完整字面块而非巨型 Table。另覆盖总 cells 与隐式 padding 两项独立预算的恰好上限和越界边界，以及 65,536 列×32,768 行（预期矩阵超过 Int 范围）的溢出回归。

## 明确边界

这是合理 CommonMark/GFM 常用聊天语法实现，**不宣称通过完整 CommonMark/GFM 官方一致性套件**。引用式链接定义、脚注、数学/图表、HTML 布局、远程 Markdown 图片、完整 HTML 命名实体表及全部 delimiter-run/容器歧义规则不在本次支持范围。内联中四个以上连续强调字符、超深嵌套或超预算歧义语法保留字面形式；复杂 lazy continuation 采用保守容器边界。不存在隐藏的 HTML 执行、隐式 URL 打开或外部解析依赖。

父集成修正：块嵌套达24层时直接Text字面降级，不再次inline解析；补闭合／未闭合波浪围栏在AST、Android URLSpan及Compose链接注解均为惰性的回归源码，尚未执行。
