- 接受`shizuku/RunShizukuCommands`作为本路候选位置，避免占用公共integration/tools目录；专属AIDL变更由02提供，01审查后合入。

- 保留`ToolEffect.WRITE`及精确WriteEffect。当前中央路径allowedWrites为空是实际缺口：不加通配授权、不把WRITE降成READ_ONLY。02交适配器与回执合同；01后续接可信用户批准入口，之前不向默认catalog开放可执行写工具。

- 首批先交实现、AIDL兼容检查、纯JVM/仪器测试与清单增量，不被真实Shizuku环境是否可用阻塞。授权/拒绝/撤销/root与shell身份真机仍由01排期，未测不能标完成。

## 03与04：ChildModelBatch只有一份生产改动

- 03拥有ChildModelBatch及RetainedChildTasks；04对ChildModelBatch的用量改动只交`public-seams.patch`，不得把整个旧文件混入独占实现补丁。
- 接受04提出的接口方向：`domain.usage.ChildUsageRecorder.record(task: ChildTaskRecord, checkpoint: RunCheckpoint)`，由04先交依赖闭合的小批类型/测试和精确源码摘要。当前只是待合入契约，不宣称主树已有此类型。
- ChildModelBatch保留现有构造兼容，尾部可选`usageRecorder: ChildUsageRecorder? = null`。03新RetainedChildTasks同样接受可选recorder，并把它传给后台实际使用的ChildModelBatch；不能只给原同步工具接线，漏掉后台子任务。
- ModelEvent.Usage交给实际子ChatRunner处理，继续使用原生requestId/attemptId/owner。RuntimeStore适配器仅转存已报告快照，不提供恢复或重发入口；禁止用回调次数/UUID伪造“供应商请求”身份。
- 04提供SQLiteChildUsageStore；01统一SQLiteRuntimeStore租约门控、恢复/关闭门闩、数据库版本及迁移、Controller只读入口。01决定最终schema版本，04不把自己的版本号和全套版本断言混入implementation.patch。
- 用量持久化异常沿真实Runner失败链封口；已发送结果未知不重试。累计快照按真实请求身份替换，允许字段变null/减少，不把cache再加进input。读覆盖与请求总量/计费完整性分开。
- 必需组合测试：同步及retained两条路径的usage、同值不同请求、终态前最后一次usage、父结束后子usage、持久失败、旧租约、stop/close；正常父结束仅封新准入，Controller关闭/撤权和用户明确子任务停止分别验证。
- 03的`RunChildTasks.kt`现作为公共接缝候选单独交给01；此例外不开放整个integration/tools目录的写入权。retained宿主由Controller持有，不能随一次父工具close销毁所有已接受子任务。

## 05：现有三条UI路径优先闭环

- 接受独立clone `/workspace/daiyu-main05-ui-v1`为本路canonical目录，不为统一命名搬动正在工作的副本。实际50a6238基线相对bfe5b17只有文档变化，可保留。
- 单会话导出使用requestCode 105；主树现有101—104保持。01接主Activity公共补丁，pending conversationId在启动选择器前冻结并按Activity恢复规则保留；结果返回不重读当前selected。
- 暂停追加只能消费已存在Accepted回调，需匹配原owner/messageId/editor generation/draft revision；Boolean排队值不消费草稿。重复点击、编辑ABA、切会话、销毁、Rejected/Unconfirmed均有断言。
- 只读任务面板先使用childTasks现有读取，不加尚未接好的停止/继续按钮，不将普通send改成sendWithChildren；加载失败不能显示为空列表的成功状态。
- MainActivity改动单独作为public-seams.patch；普通UI及专属测试归05。首批不追加Shizuku界面或图片UI，先把这三个既有合同闭环交付，避免与02/06及公共发送协议同时扩面。

## 01首批主机接线补充

- Controller-lifetime `RetainedChildTasks`共享SQLiteRuntimeStore的childTasks/childUsage；`RunCatalogTools.backgroundFactory`仅在bindOwner时绑定冻结配置，注册`start_child_tasks`；close只封口，显式stop/revoke独立请求停止。
- Controller先等父资源关闭、再等supervisor真实排空，最后关闭数据库及运行租约。后台运行期间拒绝备份/同会话删除；普通新主请求仍可使用自己的冻结配置。
- `stopChildTask(record)`匹配原始ChildRunOwner；请求结果不冒称终态，面板刷新读取持久结果。UNKNOWN不新增恢复/重发入口。
- schema v9集中合并，更新原schema v8断言；不把后台runtime对象持久化为可重跑checkpoint。
- Shizuku WRITE精确批准UI与图片公共消息协议仍是后续接缝，02/06本批按独立模块收件，不擅自注册不可授权的工具或制造图片端到端完成状态。
