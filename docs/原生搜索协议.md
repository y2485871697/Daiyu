# 原生搜索协议适配

这是接口能力与实现边界说明；任务状态和验收结果统一登记在 `docs/重构清单.md`。

模型级“搜索工具”继续使用既有布尔值和存储键，外层默认关闭；内层“原生搜索”偏好默认开启，不自动打开外层。它表示用户选择发送该接口的原生工具，不表示远端账户已开通、每轮必定检索，或同厂商所有型号都支持。原生搜索由服务端执行，不产生本地 `ToolReady`，不驱动内置浏览器。

## 本轮实现的接口族

| 接口族 | 已适配协议和字段 | 边界 |
|---|---|---|
| OpenAI GPT | Responses `tools: web_search`；Chat `web_search_options` | Chat 搜索专模不能混用客户端函数；普通 GPT 建议 Responses |
| xAI Grok | Responses 同时声明 `web_search`、`x_search` | 保留本地函数；不向 Chat 猜发旧搜索参数 |
| Google Gemini | generateContent REST `googleSearch` | 保留累计 grounding 与搜索建议；函数混用未核实，显式拒绝而非删函数 |
| Anthropic Claude | Messages `web_search_20250305` | 保留加密搜索结果与 citations；pause_turn 原样续传，不当作完成 |
| 阿里 Qwen / 百炼 | Chat `enable_search`；Responses `web_search` | Chat 不虚构结构化来源；按远端模型能力表选择 |
| 智谱 GLM | Chat `web_search` + `enable/search_result` | 提取顶层 `web_search[].link/title`，不冒充 OpenAI annotations |
| 火山 Ark / Doubao | Responses `web_search`；Chat `web_search_options` | Chat 与自定义函数互斥时提示切换 Responses；托管 DeepSeek 按 Ark 字段 |
| DeepSeek 官方 | 三协议的 `deepseek_web_search`；Responses Pro 使用普通 `web_search` | 工具类型按提供商/模型区分，不把火山托管误作官方 |
| Perplexity Sonar | 既有 Chat 兼容接口及其顶层 `citations/search_results` | 模型自带搜索；Agent Responses 完整 schema 未核实，不计为已验收 |
| MiniMax | Messages 兼容搜索、Responses `web_search` | Beta，保留服务器结果；不向 Chat 猜发搜索选项 |
| 阶跃 StepFun | Chat `tools[].type=web_search` | 分离服务器搜索 `function.results` 与本地函数；保留来源；step-5-preview 明确不支持 |
| 百度千帆 ERNIE | Chat `web_search.enable/enable_trace/enable_status/enable_citation` | `delta_tag=search_status` 是活动而非正文；顶层来源去重，实际型号以远端能力为准 |
| 腾讯混元 | Chat `enable_enhancement/search_info/citation` | 开启服务端搜索；兼容端点来源内部 schema 未核实，仅保存原始 `search_info`，不猜链接结构 |

未知兼容网关保留原 OpenAI 风格的显式 opt-in 行为，不把网关当成已核实的官方厂商。官方 host 采用精确匹配或限定的地域工作区域名；相似恶意域名不会得到官方适配身份。未硬编码会快速失效的全型号数量，也不把消费者网页搜索、独立 Search API 或 MCP 算作服务端原生模型搜索。

## 数据和失败边界

- 保留原始回复和签名，来源只追加到独立可点击来源节；链接限制 HTTP(S)，拒绝用户信息、控制符和越界索引。
- Gemini groundingChunkIndices 使用官方跨响应累计数组索引，不按每帧局部索引重排；保存响应专用元数据，但下次 POST 的 contents 投影剥离该字段。搜索建议以 Google 查询链接显示；原始 searchEntryPoint 仍保留，不执行其 HTML。
- Sonar / GLM 来源帧可只携带元数据，不要求伪造 choices；不因引用或“正在搜索”等文字生成搜索活动回执。
- Claude / MiniMax / StepFun 服务器搜索块不会进入本地工具执行队列。只有完整成功终态才确认客户端函数；无终态、非法来源、取消均不授权本地执行。
- 开关关闭时保留旧请求和 pause_turn 行为；原生搜索开启时禁止 custom body 覆盖已生成搜索字段；关闭或型号不支持时，执行合并后移除受控搜索字段，旧配置原文仍可读取和编辑。
- Messages 原生 pause_turn 的每次 HTTP 均有独立重试边界；已经完成的服务器搜索不会因后续请求恢复被重放。不设置工具续轮次数上限；连续相同的暂停结果视为无进展并结束。

## 尚未接入或尚缺证据的协议

- StepFun、混元、千帆与客户端函数同轮混用没有官方保证；实现保留函数、不虚构互斥、不把夹具成功当远端实测。
- Mistral 的原生搜索属于 Conversations / Agents，不支持 Chat Completions；需要专用协议，不能靠追加一个 Chat 字段宣称已接入。
- 混元已核实兼容 Chat 搜索开关，但其 `search_info` 内部结构仍缺官方兼容端点样例；不能把腾讯云签名 API 的 PascalCase schema 自动套到兼容端点。
- Moonshot 当前公开官方工具需 Formula / Fiber 客户端编排；Cohere 的旧搜索 connector 已弃用。两者不计作本轮服务端闭环搜索。

## 搜索工具与原生搜索两级开关（2026-11-16）

- 模型编辑器外层改为“搜索工具”；只打开外层、关闭内层时使用普通浏览器搜索。支持的模型按当前协议和端点显示展开箭头，内层“原生搜索”默认开启；不支持的模型不显示箭头与内层选项。
- 继续使用 `openai_web_search_enabled` 保存外层状态，新增 `prefer_native_search` 保存内层偏好；旧记录缺少内层键时默认开启。外层关闭不会清除内层偏好，提供商更新、模型选择及运行快照均保留两个状态。
- 请求按主开关、内层偏好、型号/协议支持与当前工具混用条件选择原生；不能混用时保留用户工具并回退普通搜索，不丢弃自定义工具。普通聊天的搜索注入受外层控制，全局浏览器授权不变；显式浏览器和子代理任务仍遵守独立授权，子代理继续禁用服务端原生搜索。
- 本次代码与本条清单同次提交；新增开关编解码、目录偏好保留、请求字段选择及展开/关闭/保存重开回归。仅云端执行测试和编译；提交时状态为待云端验证，结果以独立检查记录及准确构建SHA为准。


- 型号编辑器与实际请求还受 ModelNativeSearchSupport 的协议／型号白名单约束；上表描述低层字段适配，不表示所有协议和型号已开放。Qwen Responses 暂未进入当前型号白名单，不能把低层字段生成测试称为普通聊天可用。
