# 架构说明

当前只设 `app` 与 `core-domain` 两个必要模块，领域层不引用 Android、UI或平台类。模型适配、执行、存储与设备能力在 M0/M1 引入实际实现后再拆，不创建空模块。

S1 可启动页面从领域层读取产品名称，证明 app→domain 的编译接线。该页面为临时原生启动壳，非最终聊天界面；临时图标重新绘制，不继承旧资源，正式视觉设计另行确认。

M0 下一步：会话/消息/工具调用稳定身份、模型事件与配置接口、只读电量工具、持久化、流式展示与停止；按第一步验收基线逐项实测。未知操作先核验不重放，不把该行为留给界面自行决定。

构建SDK37.2/目标 API37，最低 API 26 是骨架兼容范围，不表示全部 ROM/Root/副屏能力已支持。领域与应用身份不与某台设备或发布证书绑定。

当前领域层额外定义ConversationId/MessageId/RunId/ToolCallId四种不同的非空身份，JUnit只验这些实际不变量和产品名称。它们是M0的薄契约，不代表已实现会话、调度或幂等。

## M0首个增量

仍为两个模块。领域ChatRunner负责有序事件、工具登记、保存后续轮、停止单一终态；app内ResponsesModel负责HTTPS/SSE，AndroidBatteryTool只读后端，ConversationDatabase负责事务和中断恢复，ChatController是进程级运行所有者。UI不解析协议。

Responses用store=false与完整input重放，显式请求加密reasoning内容；完整协议输出保存供下次发送，不将工具ID重名视为新调用。最多12轮，HTTP连接20秒/读60秒，失败或中断不自动重试。密钥不在聊天库；禁云备份及设备转移。配置冻结在发送时。

尚未完成的M0门禁：真实供应商闭环、真机强杀恢复、长历史/停止反馈性能基准与24用例完整回归。当前界面会创建一个空会话承载草稿，未创建会话草稿槽及迟到回执专项尚未验收。
