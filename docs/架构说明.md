# 架构说明

## 当前范围约束

只替换确认的 Eta 原作者实现及必要耦合，保留第三方与自研（包括视觉样式、布局、导航、交互及 UI 性能优化）；第三方维护原许可和署名，混合文件只分离 Eta 部分，不整页重写。现有新工程的会话、协议、存储与协作成果不重复重写。来源基线、实例及迁移门禁见[来源清单](来源清单.md)。下方 S1 与“M0 下一步”段落为历史阶段记录，当前实现以末尾增量说明为准。

当前只设 `app` 与 `core-domain` 两个必要模块，领域层不引用 Android、UI或平台类。模型适配、执行、存储与设备能力在 M0/M1 引入实际实现后再拆，不创建空模块。

S1 可启动页面从领域层读取产品名称，证明 app→domain 的编译接线。该页面为临时原生启动壳，非最终聊天界面；临时图标重新绘制，不继承旧资源，正式视觉设计另行确认。此句仅记录 S1 临时壳，不要求重做既有自研 UI 或丢弃自研、第三方资源。

M0 下一步：会话/消息/工具调用稳定身份、模型事件与配置接口、只读电量工具、持久化、流式展示与停止；按第一步验收基线逐项实测。未知操作先核验不重放，不把该行为留给界面自行决定。

构建SDK37.2/目标 API37，最低 API 26 是骨架兼容范围，不表示全部 ROM/Root/副屏能力已支持。领域与应用身份不与某台设备或发布证书绑定。

当前领域层额外定义ConversationId/MessageId/RunId/ToolCallId四种不同的非空身份，JUnit只验这些实际不变量和产品名称。它们是M0的薄契约，不代表已实现会话、调度或幂等。

## M0首个增量

仍为两个模块。领域ChatRunner负责有序事件、工具登记、保存后续轮、停止单一终态；app内ResponsesModel负责HTTPS/SSE，AndroidBatteryTool只读后端，ConversationDatabase负责事务和中断恢复，ChatController是进程级运行所有者。UI不解析协议。

Responses用store=false与完整input重放，显式请求加密reasoning内容；完整协议输出保存供下次发送，不将工具ID重名视为新调用。最多12轮，HTTP连接20秒/读60秒，失败或中断不自动重试。密钥不在聊天库；禁云备份及设备转移。配置冻结在发送时。

尚未完成的M0门禁：真实供应商闭环、真机强杀恢复、长历史/停止反馈性能基准与24用例完整回归。未创建会话草稿槽及会话回执专项见后续增量记录。

## 协议夹具增量

ResponsesStream按item_id和content_index聚合内容，分片done只修正对应分片；失败/停止保留已接收文本。工具在完整成功终态校验后才执行，最终重复call_id、非completed调用、缺少确认或incomplete均拒绝。生产连接始终HTTPS，内部连接工厂仅供平台测试注入内存连接，不增加可配置传输入口。

新增无真实密钥的ResponsesModel→SSE→ChatRunner协议夹具，包括两轮工具、加密reasoning重放、跨消息协议重放、多分片失败保留、重复/未完成调用零执行、拒绝文本/重复事件、停止、HTTP/内容类型失败、截断/缺失终态。真实供应商、真机强杀和性能仍待验证，不将夹具等同完整M0验收。

## 会话可靠性增量

数据库v2新增独立composer草稿槽，v1原会话/消息/序号/草稿原样升级，不把旧空会话自动迁为槽。首次发送在同事务创建会话、插入两消息和清空新槽；失败回滚保稿。消息流式save仅更新已有RUNNING消息，绑定会话/消息/运行/角色，终态或删除后迟到回执拒绝，不能复活消息。分页限定1至200条。

新建和冷启未选择时进入独立槽，不创建会话；运行中允许切换/编辑其他会话，仍同时一个运行，禁止删除运行所属会话。进程级选区随Activity重建保留，跨进程不保证。发送仍在主线程同步事务，网络回调从不清草稿，因此未引入异步提交版本/事件日志。现有单线程运行不允许旧RUNNING快照并行覆盖，此增量不声称任意多写入方乱序安全。

新增存储/Controller/Activity夹具：新槽回滚与重开、删除/身份/终态、122条分页与恢复、v1升级、闩锁控制迟到回调保留三槽草稿、运行中实际界面切换和Activity重开。冷启强杀/真实供应商/性能与完整M0验收仍需单独实测。


## 自研正文重复保护复用增量

保留旧代鱼纯Kotlin重复检测算法及7项测试，仅适配包名。ChatRunner在保存/发布前检测delta与累计final快照，拒绝后取消运输且不执行pending工具，保留已确认内容与工具结果并写统一失败终态。不增加数据库版本、UI组件、重连策略或生产依赖。每次模型请求独立窗口；工具真正执行后的续轮重置，登记调用不重置。reasoning文本尚无领域事件，本轮只接通可见正文。


## 第二步保留接线：可观察思考摘要

领域ModelEvent增加独立ReasoningDelta/ReasoningFinal；思考摘要只检测不发布正文/不新增存储块。ResponsesStream按summary_index聚合并输出累计ReasoningFinal，完成事件无/空summary不清除已观察窗口；明确的空文本按纠正快照处理。协议成功终态、调用确认与密文回放规则不变。

ChatRunner复用原自研算法建立正文/摘要分窗。非空白的新正文进展重置摘要窗口并记录已观察基线，重复正文快照不算进展；ToolReady仅登记，不清窗。每工具续轮重建窗口。拒绝先取消并固定失败类型，best-effort取消不覆盖已经确定的完成/停止/失败结果。

当前压缩队列/重连attempt生命周期尚未建立，保留迁移候选ConversationCompressionSendPolicy、ProviderEventDeliveryGate先登记来源和接口缺口，不搬孤立函数或声称相关能力已接通。全量M0、真实供应商、真机强杀恢复与性能仍另行验收。


## 保留接线：窗口刷新率

core-domain保留既有RefreshRatePolicy纯函数及原测试，app MainActivity仅接入resume请求、pause所有权回滚和取消延迟回调；preferredDisplayModeId保持原样，不引入全局显示策略或旧Compose业务骨架。刷新率请求不修改UI视觉，平台可以按功耗/显示模式忽略请求。
