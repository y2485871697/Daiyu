# 已暂停文本追加的后端合同

本增量仅覆盖已暂停运行中的纯文本追加，不代表完整 P14。UI 由另一路接线；流式、工具执行、WAITING_USER、媒体及自动清稿不在本增量中。

## 入口与结果

`ChatController.admitSupplement(owner, messageId, text, complete)`：

- `owner` 为原 assistant 的消息、会话、运行身份；不得使用当前任意消息替代。
- `messageId` 由调用者为本次用户动作生成并保留，不能拿初始用户消息或已有 segment ID 复用。
- 仅 PAUSED 接受排队。返回 Boolean **只表示内存排队**，不是持久接受。
- 最终 `complete(SupplementAdmission)` 投递主线程。后端不清草稿、不隐式 resume。

结果：

- `Accepted(messageId)`：对应 user 行与包含它的检查点已同事务提交；不表示 provider 收到、执行或完成。
- `Rejected(messageId)`：本次未获得准入；可能为阶段、身份或重复 ID 冲突，不应推断该 ID 从未有过历史提交。
- `Unconfirmed(messageId)`：提交抛错，无法确认是否已经提交。运行封口，不自动重提、恢复所有权或重发模型请求。

UI 只能在 Accepted 对应原 editor owner、草稿版本和 messageId 仍匹配时消费其原草稿。不得清除在等待期间新编辑的内容。Boolean、queuedSupplements 数量或消息已显示均不替代 Accepted。

## 持久化与停止

Runner 是唯一 checkpoint revision 写入者；控制线程仅排队和唤醒。PAUSED worker 在锁外调用 `AtomicSupplementRuntimeStore.commitSupplement`，SQLite 复用原 owner/revision/process_owner CAS，一笔事务插入文本 user、更新 checkpoint 与 assistant，任一环失败整笔回滚。数据库 schema 和 checkpoint v4 格式不变。

显式 resume 前排队的提议先逐项提交。resume 才将已接受队列交给模型；独立 user 行与 assistant history segment 经原 MessageHistory 校验去重。

stop/close 不等待准入 IO：已捕获且提交成功的提议仍返回 Accepted，但不再启动模型；未捕获提议最终 Rejected。进程恢复保留用户内容，旧 assistant 仅中断，不重建 continuation、不重 POST 或重放工具。相同消息 ID 不覆盖、不忽略成功、不自动再次准入。
