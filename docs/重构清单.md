# 代鱼重构清单

本文件是重构工作的唯一进度清单。项目相对路径：`docs/重构清单.md`；手机路径：`/workspace/代鱼/docs/重构清单.md`；电脑路径：实际获准 Git 根目录下的同一相对路径（仅限 `E:\daiyu` 内）。

## 目标与固定边界

- 代鱼是独立项目，不是 Eta 改名换皮：替换 Eta 原作者的核心实现和宿主封装，形成独立架构、运行及维护链。
- 保留用户明确确认的自研功能及其实现、UI、配置、数据契约、交互和必要测试；第三方主体保留来源、适用许可证和署名。引用第三方不撤销自研功能的保留决定。
- 只对影响保留/替换的混合部分按需拆分，不以全仓逐行归属审计为开发前置。保留地图完成不等于新项目迁移或业务验收完成。
- 自研侧边栏、子代理UI、会话弹窗、图标设置等外观保留；聊天页/设置页等非自研外观由用户安排 Gemini 重构，必须保留业务接口与交互。
- 旧 Eta 工作树、既有脏改动和历史 APK 不动；仅新仓库 `y2485871697/Daiyu` 的 `main`，不强推；不重派/重合并/重构建已完成工作。

## 使用与及时更新规则

1. 每次重构前读本清单和相关条目的证据，复用已有成果；先确认旧任务、候选和代码基线，不从头重复。
2. 为每项使用稳定ID。状态只能是：待迁移、待重构、进行中、待集成、待验收、阻塞、已完成。范围很大时以子项记录真实完成部分，不把整个模块一并勾完。
3. 每完成一个功能立即更新本文件，和功能代码同次提交；部分完成或阻塞也立即写清已完成部分、具体阻碍和下一步，不等全部重构结束。
4. 更新记录写：ID、入口/实现路径、源码提交、真实验证范围与结果、证据位置、剩余项；CHECK用准确SHA/命令/环境/退出码，APK用run/attempt/BUILD_SHA。提交记录可引用已存在代码SHA；代码与清单同次提交时注明“随本次提交”，提交后以Git历史定位，不为了填写自身SHA再制造循环提交。
5. 只有生产入口、参数/状态传递、持久化和失败/暂停/停止/恢复路径已接通，相关必要验证通过，且没有任务内阻碍，才标已完成。模型自述、候选commit、类型检查或模块编译不替代业务验收；未运行测试写未运行。
6. 子代理报告按ID交付证据与剩余项；父代理核验后统一改状态。并行写代码时避免同改本文件；不让子任务结束自动变成已完成。
7. 第三方精确版本或许可缺项附在相关行，不阻塞其它已明确保留项，也不将待核部分默认认原创。
