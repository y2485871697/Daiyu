# 页面帧率与帧耗时日志

## 手工测试

这套入口随新源码打包后生效；更新源码不改变手机当前已安装 APK。

1. 在设置现有“记录诊断日志”开关中开启记录。不新增权限或测试悬浮窗。
2. 如需独立一轮样本，先“清除日志”，再依次操作聊天滚动、流式回复、输入框与键盘、侧栏、各设置子页、弹窗、终端和浏览器。
3. 回到设置并关闭记录，再点“导出日志”，保存 `daiyu-diagnostics.json`。关闭保留历史，清除只删除本套诊断/帧日志，不改聊天、文件或执行账本。
4. 优化前后使用相同 APK 变体、设备刷新率、页面数据和操作。诊断关闭/开启的额外开销要另做对照，不把记录器存在当成性能达标。

## 覆盖与归属

- OAuth登录和附件接收的独立Activity也接入同一开关；多Activity各自登记刷新屏障，不互相覆盖。内部虚拟屏移交遮罩不作为普通用户页面。
- 主导航使用真实 `visualRouteKey`，包括侧栏和 `PageBackStack` 的最深有效子路由；不拿返回动画截图的 contentKey 冒充当前页面。
- 两个公共 Scaffold 加封闭产品标题标签。用户自定义标题、提供商/会话/任务ID、网址与路径不写日志；未知子路由/标题归为 `detail`。
- 非路由切换另标聊天会话边界、终端环境/模式与会话边界、Linux基础/文件页、提供商连接/模型页、浏览器标签边界及历史/下载/设置面板。状态主键只触发分段，不序列化标识值。
- 通用 Compose Dialog、AlertDialog、预览/底部弹层、生产源码内直接调用的 Miuix WindowDialog，以及调用公共准备函数的原生 Dialog，注册各自真实 Window 的 FrameMetrics。弹窗帧不冒充主窗口帧。
- 仅前台恢复态安装 Window listener；暂停时移除并刷新最后一段。首次开启后复用空闲采集线程，Activity销毁时排空并退出；默认关闭时不创建采集线程或帧文件。
- 外部系统页面/输入法/其他App窗口、非 Window 的 Popup，以及独立桌面女仆 Surface 的内部绘制不是本 Window 日志的独立呈现测量对象。浏览器 WebView 数据反映所在窗口的渲染，不是网页浏览器的独立 compositor present 时间。

## 格式

联合导出为合法单个 JSON，`format=daiyu-diagnostics`、`version=2`。旧 `enabled`、`events`、`privacy` 仍在根对象；事件持久化文件保持原严格 v1，不在事件列表塞逐帧事件。

新增 `frame_performance` 对象：`format=daiyu-page-frames`、`version=1`，包含 `columns`、`windows`、写入/队列/采集失败及残缺行计数。`windows` 是按约一秒、页面、刷新率、上下文或生命周期边界拆分的采集段。

每段含：

- 页面、内容/离散状态标签、窗口类别、SDK及应用版本；
- 墙钟毫秒 `time_ms`、单调时钟 `start_vsync_ns`、首末样本跨度 `span_ms`、观测刷新率；
- 帧数、`callback_fps`、平均 total 耗时、P50/P90/P95/P99/最大耗时；
- 可判定帧数、超预算帧数/比例、超过50/100/700毫秒帧数、首绘数和框架丢报数；
- `frames`：按照 `columns` 顺序保存每帧 intended-vsync 相对时间、total、budget，以及 unknown-delay、input、animation、layout/measure、draw、sync、command-issue、swap-buffers、GPU 阶段耗时、丢报数和首绘标记。耗时为微秒，字段名带单位的以字段名为准。

API31及以上优先用平台 deadline；否则用真实观测刷新周期估算预算。无法取得的指标为 `-1`；不可判定比例/单帧不足以计算的 FPS 为 `null`，不补零。首绘保留原始样本及各耗时阈值计数，仅从超预算比例分母排除。

`callback_fps` 是该段渲染回调的 `(帧数-1)/首末vsync跨度`，**不是屏幕实际呈现 FPS**；静止页面不持续绘制，不将其少量样本解释成掉帧。框架 callback 丢报和 writer 队列丢弃也不是显示掉帧数。total 不是完整输入到硬件呈现延迟；本日志不代替既定物理设备性能验收。

## 存储与完整性

逐帧先进入有界内存段，不逐帧写盘。专用后台 writer 批量写 JSONL，队列最多8段；每段最多240帧；最多3个2MiB文件，约6MiB，满后淘汰最旧文件。每帧读取 epoch 不争用磁盘锁。日志不无限增长，轮转后的旧测试需要之前及时导出。

导出在后台冻结当前采集并等待 writer 截点，成功取得源快照后才截断 SAF 目标。清除推进 capture epoch，清除前队列和未完成段不能重新写回。关闭记录保留已接受日志。追加失败尽量回滚文件长度；进程中断留下的残缺行在导出时跳过并计数，不连带销毁有效事件日志。

日志本身会增加对象分配和后台IO，当前没有真机开销达标结论。若 `queue_dropped_windows`、`write_failures`、`capture_failures`、`corrupt_rows_skipped` 或段内 `callback_drops` 非零，样本不应宣称完整无损。
